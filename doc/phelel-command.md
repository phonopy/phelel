(phelel_command)=
# `phelel-init` and `phelel` commands

Command-line tools perform steps 1 and 3 in {ref}`the el-ph calculation
workflow <workflow_minimal>`. Their usage parallels that of the `phonopy-init`
and `phonopy` commands in [phonopy](https://phonopy.github.io/phonopy/) for
phonon calculations.

- `phelel-init` generates supercells with displacements (step 1).
- `phelel` calculates the derivatives of local potentials and PAW strengths
  from the results of the VASP calculations of these supercells (step 3).

The following example demonstrates the two steps:

```bash
% phelel-init -d --dim 2 2 2 -c POSCAR-unitcell --pa auto --pm

# After running VASP calculations in directories corresponding to displacements:

% phelel --cd disp-000 disp-001 disp-002 disp-003 disp-004 --fft-mesh 18 18 18
```

The numbers given to `--fft-mesh` depend on the crystal and on the VASP
calculation; see {ref}`phelel_fft_mesh_option`.

(phelel_init_command)=
## Generation of displacements in supercell by `phelel-init`

Supercells with displacements can be generated by combining the following
command options. For example:

```bash
% phelel-init -d --dim 2 2 2 -c POSCAR-unitcell --pa auto --pm
```

Here, `POSCAR-unitcell` is the unit cell structure in VASP POSCAR format. After
this operation, a file named `phelel_disp.yaml`, containing information about
the displacements, is created. Additionally, the supercell structures `SPOSCAR`,
`POSCAR-001`, and so on are generated.

### `-d`

This generates supercells with systematically introduced displacements. The
displacements are determined by crystal symmetry, with exactly one displacement
applied in each supercell. `phelel-init` needs this option.

### `--dim`

Three or nine integer values specify the supercell shape with respect to the
unit cell structure indicated by the `-c` option. If nine values are provided,
they correspond to the supercell matrix as defined in the [phonopy
documentation](https://phonopy.github.io/phonopy/setting-tags.html#dim). If
three values are given, they represent the diagonal elements of the supercell
matrix, meaning each axis of the input unit cell is simply extended by the
corresponding integer factor.

```bash
% phelel-init --dim 2 2 2 [OPTIONS]
```

```bash
% phelel-init --dim 0 1 1 1 0 1 1 1 0 [OPTIONS]
```


### `-c`, `--cell`

Unit cell structure is specified.

```bash
% phelel-init -c POSCAR-unitcell [OPTIONS]
```

### `--pa`, `--primitive-axis`

Transformation matrix from the input unit cell to the primitive cell. It is given
either as nine values forming the 3x3 matrix `[[v1, v2, v3], [v4, v5, v6], [v7,
v8, v9]]`, or as `auto` to search the primitive cell automatically. This works
the same way as the `PRIMITIVE_AXES` tag in
[phonopy](https://phonopy.github.io/phonopy/setting-tags.html).

```bash
% phelel-init --pa auto [OPTIONS]
```

### `--pm`

Unless specified, only one directional displacement is selected among
symmetrically equivalent displacements in the opposite direction. With this
option specified, both directions are included in the generated supercells with
displacements. Use of this option is recommended.

```bash
% phelel-init --pm [OPTIONS]
```

### `--magmom`

Magnetic moments of the atoms in the unit cell are specified in the order of
the atoms. One value per atom is given for a collinear calculation
(`ISPIN = 2`), and three values, the x, y and z components, per atom for a
non-collinear calculation (`LNONCOLLINEAR = .TRUE.`). As in the MAGMOM tag of
VASP, `4*1` means `1 1 1 1`. Such values are enclosed in quotes, because the
shell may expand `*`.

```bash
% phelel-init --magmom 2 -2 [OPTIONS]
% phelel-init --magmom "4*1 4*-1" [OPTIONS]
% phelel-init --magmom 0 0 2 0 0 2 [OPTIONS]
```

The magnetic moments are stored in `phelel_disp.yaml`. The MAGMOM line for the
supercell is written in the file `MAGMOM`, which is used in the INCAR of the
VASP calculations of the supercells.

Without `--magmom`, the symmetry operations are found from the positions and
the species of the atoms, and they act on the atomic positions. With
`--magmom`, the magnetic moments are also included in what the symmetry
operations act on. Each operation then maps the atomic positions and the
magnetic moments together, and it may be combined with time reversal, which
reverses the magnetic moments. These operations form the magnetic space group.
The displacements and the symmetrization of the derivatives use the same
operations.

In a spin-polarized or non-collinear VASP calculation, the local potential and
the PAW strengths have spin parts, and the symmetry operations are applied also
to these spin parts in the symmetrization. When the magnetic moments are not
included in the symmetry operations, an operation that maps the atomic
positions but not the magnetic moments may be used. An example is an operation
that moves an atom with an up spin onto an atom with a down spin. The
derivatives obtained with such an operation are wrong.

When the magnetic moments are zero in the VASP calculation, zeros are given by
`--magmom`. The default value of MAGMOM in VASP is not zero in a
spin-polarized or non-collinear calculation, so the file `MAGMOM` with zeros
makes the VASP calculation start from zero magnetic moments. With zeros, every
operation found from the atomic positions is used both without and with time
reversal.

The number of values has to fit the VASP calculation, one or three per atom,
also when all the values are zero. Otherwise `phelel --cd` stops with an
error. When `--magmom` is not used and the VASP calculation is spin-polarized
or non-collinear, `phelel --cd` shows a warning.

`phelel --cd` also applies every symmetry operation to the PAW strengths Dij
of the perfect supercell. Dij should be unchanged by every operation, and a
warning is shown when an operation changes it by more than 0.01 eV. This
happens when the magnetic moments included in the symmetry operations do not
describe the magnetic state of the VASP calculation, for example when the sign
or the direction of a magnetic moment differs from that in the VASP
calculation, or when the VASP calculation converged to another magnetic state.

## Calculation of derivatives of potentials by `phelel`

After running VASP calculations to calculate local potentials and PAW strengths
under the configurations of displacements in supercells, those data are stored
in certain files. Those are read and then the derivatives are computed by the
following command, e.g.,

```bash
% phelel --cd disp-000 disp-001 disp-002 disp-003 disp-004 --fft-mesh 18 18 18
```

Here `disp-000`, `disp-001`, ..., indicate the directories in which VASP
calculations were performed for respective supercells with displacements, i.e.,
`SPOSCAR`, `POSCAR-001`, ..., as generated by `phelel-init`. The displacements
are read from `phelel_disp.yaml` in the current directory. Another
`phelel_disp.yaml`-like file can be given as the argument of `phelel`:

```bash
% phelel phelel_disp.yaml --cd disp-000 disp-001 disp-002 disp-003 disp-004 --fft-mesh 18 18 18
```

### `--cd`, `--create-derivatives`

This triggers two sequential operations. First, VASP calculation results are
collected from the specified directories in the order given by the command
options. Next, using these collected data, the derivatives of local potentials
and PAW strengths with respect to displacement are calculated and stored in
`phelel_params.hdf5`. `--cd` needs `--fft-mesh`.

When every directory has `LOCAL-POTENTIAL.bin`, which VASP writes with
`LWAP = .TRUE.`, the local potentials and the PAW strengths are read from
`LOCAL-POTENTIAL.bin`, `PAW-STRENGTH.bin` and `PAW-OVERLAP.bin`, with
`inwap.yaml`. Otherwise they are read from `vaspout.h5`. VASP 6.6.1 and older
do not write the local potential correctly in `vaspout.h5` for ISPIN = 2 or
LNONCOLLINEAR = .TRUE., and `phelel --cd` stops with an error when it would read
such a local potential. Run VASP with `LWAP = .TRUE.` for these calculations.
`velph init` writes `lwap = true` for the phelel calculations of these kinds.

(phelel_fft_mesh_option)=
### `--fft-mesh`

Three integers give the FFT mesh of the primitive cell on which the derivatives
of the local potentials are written in `phelel_params.hdf5`. Give the FFT mesh
(NGX, NGY, NGZ) that VASP uses for the primitive cell in the electron-phonon
calculation. `velph phelel differentiate` computes this mesh from ENCUT and PREC
of the electron-phonon calculation and gives it to phelel.

(phelel_nufft_option)=
### `--nufft`

VASP gives the change of the local potential on the FFT mesh of the supercell,
and phelel evaluates its Fourier series at the points of the mesh given by
`--fft-mesh` and at these points moved by the symmetry operations. `--nufft`
chooses how the series is evaluated.

| `--nufft`           | Evaluation                                                                  | Reciprocal lattice vectors |
| ------------------- | --------------------------------------------------------------------------- | -------------------------- |
| `finufft` (default) | [finufft](https://finufft.readthedocs.io/) to the accuracy of `--finufft-eps` (1e-6 by default) | box                        |
| `native`            | FFTs with NumPy, without the approximation of finufft                       | shortest                   |
| `native-box`        | FFTs with NumPy, without the approximation of finufft                       | box                        |

The Fourier coefficients of the FFT mesh of the supercell are periodic in the
reciprocal lattice vectors, with the period of the mesh. Each coefficient is
given to one of the vectors equal to each other modulo this period, and the
choice changes the series between the points of the mesh. "Shortest" gives it
to the shortest vectors, divided equally among those of the same length, so
that the series keeps the symmetry of the crystal and is real (Hermitian with
non-collinear spin). "Box" gives it to the vectors in a box, which for an even
mesh number N contains +N/2 but not -N/2, and the series does not keep them.
When the points given by `--fft-mesh` are on the FFT mesh of the supercell, the
choice does not change the derivatives. Otherwise those of `native` differ from
those of the others, by about 1e-5 relative in the examples tested.

The derivatives of `native-box` and `finufft` differ by the error of finufft.
`--finufft-eps` cannot be given with `native` or `native-box`. By default,
finufft runs on all the CPU cores, and `native` and `native-box` run on one
core.

In a configuration file, `NUFFT = native` is the same as `--nufft native`.

### `--config`

The settings are read from the configuration file given by `--config`, e.g.,

```bash
% phelel --config phelel.conf --cd disp-000 disp-001 disp-002 disp-003 disp-004
```

with `phelel.conf`

```
FFT_MESH = 18 18 18
```

The argument of `phelel` is always read as a `phelel_disp.yaml`-like file. A
configuration file given as the argument is an error.

The supercell matrices are those in `phelel_disp.yaml`, to which the
displacements belong. `DIM` and `DIM_PHONON` in the configuration file do not
replace them, and `phelel` reports the ones given if they differ.

## Commands of earlier versions

Earlier versions of phelel used a single `phelel` command to generate the
supercells with displacements and to calculate the derivatives. The two steps
are now done by two commands:

| Earlier command                          | Command now                                 |
| ---------------------------------------- | ------------------------------------------- |
| `phelel -d --dim 2 2 2 -c POSCAR-unitcell` | `phelel-init -d --dim 2 2 2 -c POSCAR-unitcell` |
| `phelel --cd disp-000 ...`               | `phelel --cd disp-000 ... --fft-mesh ...`   |
| `phelel-load phelel_disp.yaml --cd ...`  | `phelel phelel_disp.yaml --cd ...`          |

`phelel` stops with an error when it is given an option of `phelel-init`, such
as `-d`, `-c` or `--dim`, and the error tells to use `phelel-init`. With `-c`,
the earlier `phelel --cd` also read a crystal structure in a POSCAR-like file;
`phelel` reads it only from `phelel_disp.yaml`. `phelel-load` still works as
`phelel` and prints that it is deprecated.
